# Расчёт теплообмена в противоточном слое

Учебное веб-приложение для расчёта температур материала и газа по высоте плотного продуваемого слоя. Пользователь задаёт исходные параметры, получает таблицу и графики, а затем может сохранить расчёт под своим аккаунтом.

## Что уже работает

- Расчёт без регистрации: исходные данные проверяются в форме и на сервере.
- Таблица температур и два графика: температуры материала и газа, а также разность температур по высоте слоя.
- Итоговые значения: температуры материала и газа на выходе, тепловой поток.
- Восстановление последнего расчёта после обновления страницы по параметрам из браузера.
- Регистрация по логину и паролю, вход и выход из аккаунта.
- Сохранение именованных вариантов, просмотр списка и открытие варианта с заполнением формы.

Каждый вариант принадлежит пользователю, который его сохранил. Сервер проверяет владельца и при получении списка, и при открытии по ID. В базе сохраняются название и исходные параметры; при открытии варианта расчёт выполняется заново.

## Из чего состоит проект

Фронтенд написан на React и TypeScript: Vite, React Router, Zustand, React Hook Form, Zod, Recharts и Tailwind CSS. На сервере — Express, Prisma и PostgreSQL.

Пароли хранятся в виде хешей Argon2. Для входа используются серверные сессии в PostgreSQL: браузер получает HttpOnly-cookie с идентификатором сессии.

```text
apps/
  api/                  Сервер, расчётная модель, Prisma и миграции
  web/                  Интерфейс приложения
  packages/
    contracts/          Общие Zod-схемы и TypeScript-типы API
docker-compose.yaml     Локальная PostgreSQL
```

Это monorepo на npm workspaces. PostgreSQL запускается в Docker, а API и фронтенд — локально через Node.js.

## Как запустить локально

Понадобятся Node.js 22.12 или новее и работающий Docker с Docker Compose. Ниже команды для терминала macOS/Linux. Начинайте из корня репозитория.

Установите зависимости и создайте файл настроек:

```bash
npm install
cp apps/api/.env.example apps/api/.env
```

Сгенерируйте секрет для подписи cookie:

```bash
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

Скопируйте полученную строку в `SESSION_SECRET` в файле `apps/api/.env`. Остальные значения из примера подходят для локальной базы из Docker Compose. Файл `.env` исключён из Git.

Затем запустите базу, примените миграции и сгенерируйте Prisma Client:

```bash
docker compose up -d --wait database
cd apps/api
npx prisma migrate deploy --config prisma7.config.ts
npx prisma generate --config prisma7.config.ts
cd ../..
npm run dev
```

Приложение откроется по адресу <http://localhost:5173>. Проверить доступность API можно через <http://localhost:3001/api/health>.

Для первого расчёта достаточно открыть приложение и заполнить исходные данные. Чтобы сохранять варианты, создайте аккаунт через страницу регистрации. После регистрации вход выполняется автоматически.

## База данных

Схема находится в `apps/api/prisma/schema.prisma`. Таблица `User` хранит аккаунты, `CalculationVariant` — варианты с ID владельца. Таблицу `session` создаёт библиотека хранения сессий при первом сохранении сессии.

Для подключения через DBeaver или другой клиент используйте локальные настройки из `docker-compose.yaml`:

| Параметр | Значение        |
| -------- | --------------- |
| Host     | `127.0.0.1`     |
| Port     | `5433`          |
| Database | `heat_exchange` |
| User     | `heat_user`     |
| Password | `heat_password` |

Посмотреть данные можно и через Prisma Studio. Из папки `apps/api` выполните:

```bash
npx prisma studio --config prisma7.config.ts
```

Данные базы сохраняются в Docker volume. Остановка контейнера через `npm run db:down` их не удаляет.

Если вы меняете схему Prisma, создайте миграцию из `apps/api`:

```bash
npx prisma migrate dev --config prisma7.config.ts --name название_изменения
npx prisma generate --config prisma7.config.ts
```

Инструкция первого запуска рассчитана на новую базу. Если база осталась от версии без пользователей и содержит варианты, перед миграцией с обязательным `userId` нужно решить, кому принадлежат эти записи, и подготовить перенос данных.

## Команды для разработки

| Команда из корня проекта             | Что делает                                              |
| ------------------------------------ | ------------------------------------------------------- |
| `npm run dev`                        | Собирает контракты и запускает API вместе с фронтендом  |
| `npm run dev:api`                    | Запускает только API                                    |
| `npm run dev:web`                    | Запускает только фронтенд                               |
| `npm run build`                      | Собирает контракты, API и фронтенд                      |
| `npm test -w @counterflow/contracts` | Проверяет общие схемы и типы API                        |
| `npm run db:up`                      | Запускает локальную базу                                |
| `npm run db:down`                    | Останавливает и удаляет контейнер базы, сохраняя volume |
| `npm run format`                     | Форматирует проект через Prettier                       |
| `npm run format:check`               | Проверяет форматирование без изменения файлов           |

Общий пакет подключается как `@counterflow/contracts`. В нём описаны запросы и ответы расчёта, вариантов и авторизации. Преобразование строк из полей формы в числа остаётся на фронтенде.

После изменения контрактов во время разработки пересоберите пакет:

```bash
npm run build -w @counterflow/contracts
```

При запуске только API или только фронтенда контракты тоже должны быть предварительно собраны. Сгенерированные файлы `dist` и Prisma Client в Git не сохраняются.
